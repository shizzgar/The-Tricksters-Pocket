# Полный экспорт трассы

[Обзор](../README.md) · [Trajectory](agent-runtime/trajectory-and-termux-skills.ru.md) · [Документация](README.md)

Вверху **«+ → Трассировка диалога»** нажмите **«Экспорт всей трассы»** и выберите место сохранения ZIP через системный диалог Android. Кнопка доступна и при открытом инспекторе операции. Экспорт охватывает корневой диалог и связанные записанные трассы его подагентов.

Это полный снимок сохранённых журналов, независимо от поиска, фильтров, выбранного запуска и текущей страницы. Даже если экран показывает только последние 600 событий или более старое окно, архив читает весь журнал с начала. Инструменты при экспорте не запускаются.

## Что входит

- Нормализованные запросы модели: системные/пользовательские/ассистентские сообщения, определения tools и параметры, которые записал runtime.
- Ответы и потоковые chunks: текст, reasoning, возвращённый провайдером, аргументы tool calls и usage/тайминги, если они сохранены.
- Запуск и результаты tools: записанные входы и выходы, stdout/stderr, статусы, ошибки и идентификаторы связей.
- События compaction, задачи, checkpoints и переходы состояния.
- Дочерние журналы подагентов по записанным `child_conversation`, включая вложенные запуски. Циклические ссылки не дублируют сессии.
- Исходные записи и сжатые payload, а также удобные для чтения несжатые JSON. Сохраняются и не привязанные к завершённой записи payload-файлы, оставшиеся после сбоя.

Текущий диалог и каждый подагент получают отдельный момент снимка. Агент может продолжать работу во время записи ZIP; события после момента снимка своей сессии попадут в следующий экспорт. Независимые диалоги и история родительской ветки автоматически не добавляются.

## Формат архива — schema 1

| Путь | Содержимое |
|---|---|
| `README.txt` | Самодостаточное описание формата на английском |
| `manifest.json` | ID корневого диалога, версия приложения, время, перечень сессий, число событий и найденных проблем |
| `issues.jsonl` | По одной диагностической записи на строку; пустой файл при отсутствии проблем |
| `sessions/<uuid>/events.jsonl` | Оригинальный индекс событий с цепочкой хешей, в порядке записи |
| `sessions/<uuid>/payloads/<hash>.json` | Полное распакованное содержимое события без UI-превью и обрезки |
| `sessions/<uuid>/raw-payloads/<hash>.json.gz` | Исходные сжатые байты; сохраняются также повреждённые blobs |
| `sessions/<uuid>/task.json` | Сохранённое состояние задачи, если есть |
| `sessions/<uuid>/uncommitted-*.fragment` | Сохранённые фрагменты оборванных записей, если есть |

Поле `payloadHash` в событии указывает на JSON в каталоге `payloads` той же сессии. Несколько событий могут ссылаться на один payload. Хеш вычислен от исходных распакованных байтов; форматирование JSON меняет его.

Пример чтения после распаковки, стандартный Python 3:

```python
import json
from pathlib import Path

root = Path("unpacked-trace")
manifest = json.loads((root / "manifest.json").read_text(encoding="utf-8"))
for session in manifest["sessions"]:
    directory = root / "sessions" / session["id"]
    with (directory / "events.jsonl").open(encoding="utf-8") as events:
        for line in events:
            record = json.loads(line)
            path = directory / "payloads" / (record["payloadHash"] + ".json")
            payload = json.loads(path.read_text(encoding="utf-8"))
            print(json.dumps({"session": session["id"], "record": record,
                              "payload": payload}, ensure_ascii=False))
```

Пример рассчитан на архив без ошибок. Если `warning_count` больше нуля, сначала посмотрите `issues.jsonl`: файл или запись могли отсутствовать либо быть повреждены.

## Ошибки, отмена и полнота

Экспорт проверяет цепочку индекса и SHA-256 распакованных payload. Повреждение или отсутствующий дочерний журнал не скрываются: доступные оригиналы сохраняются, проблема попадает в `issues.jsonl`, интерфейс показывает число предупреждений, а `manifest.complete` становится `false`.

`complete: true` означает, что при чтении снимка не обнаружены проблемы хранения. Это не доказательство того, что runtime записал все события за всё время существования диалога. Экспорт не может восстановить то, что не записывалось старой версией, скрытые рассуждения модели, полный HTTP-трафик или содержимое внешних вложений, на которые журнал хранит только ссылки. Сохранённые результаты tools экспортируются целиком; данные, которые сам tool не вернул или ранее ограничил, заново не запрашиваются.

Во время экспорта доступна отмена. При ошибке записи или отмене приложение пытается удалить созданный неполный файл; некоторые document providers этого не поддерживают, поэтому оставшийся файл нельзя считать завершённым архивом. Временные файлы приложения очищаются.

Архив содержит полные записанные промпты, команды и результаты. Проверьте содержимое перед публикацией в issue или передачей другому человеку. Экспорт не выполняет replay и не отправляет архив автоматически.

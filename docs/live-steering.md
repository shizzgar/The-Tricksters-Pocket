# Уточнения во время работы агента

[Обзор](../README.md) · [Документация](README.md) · [Трассировка](trace-export.md)

Пока агент работает, напишите уточнение в обычном поле ввода и нажмите отправку. Оно появится в очереди над вводом с пояснением, когда будет принято. Текущая задача продолжится с новым сообщением после ближайшей завершённой операции. Отдельный переключатель не нужен; это работает и с выключенным автономным продолжением.

## Когда агент получает сообщение

| Текущая операция | Момент подхвата |
|---|---|
| Ответ модели, включая reasoning и текст | После завершения текущего запроса, до следующих локальных tools или запроса модели |
| Локальный tool call | После возврата и сохранения результата текущего вызова |
| Сжатие контекста | После окончания сжатия, до следующего запроса модели |
| Ожидание следующей попытки при сбое сети | Новое уточнение будит ожидание; подхват идёт перед новой попыткой |
| Запрос подтверждения tool | Сначала нужно разрешить или отклонить ожидающий вызов; уточнение не выдаёт разрешение автоматически |

Reasoning и ответ часто приходят в одном HTTP-потоке. Изменить уже отправленный запрос без его прерывания нельзя: уточнение передаётся модели в следующем запросе, после завершения этого потока. Ждать итогового ответа всей агентской задачи не требуется.

Если модель заранее объявила несколько tool calls, уже запущенный вызов завершается. Оставшиеся ещё не начатые вызовы закрываются результатом `not_executed / superseded_by_user_input`. Модель видит выполненный результат и уточнение, затем пересматривает следующие действия. Это сохраняет пары tool call/result и не запускает устаревший план после нового указания.

## Очередь и Stop

- Несколько готовых уточнений принимаются вместе, в порядке отправки, отдельными пользовательскими сообщениями в том же запуске задачи.
- До подхвата сообщение можно изменить или удалить. Редактирование первого сообщения удерживает следующие, сохраняя порядок.
- Статус «Принимается…» означает короткий этап сохранения; редактирование и удаление этой записи на нём недоступны.
- **Stop** останавливает работу и приостанавливает очередь. Ещё не принятые уточнения остаются в очереди, принятые — в истории. Они не запускают новый запрос после Stop автоматически.
- Голосовые сообщения с отдельным ожиданием озвученного ответа, отправка без ответа и перегенерация исторического диапазона сохраняют прежнюю последовательную обработку.

Ожидающая очередь хранится в памяти текущего процесса, как и раньше. После принятия сообщение записано в историю диалога; уничтожение Android-процесса до принятия может потерять ещё ожидающий ввод.

## Для отладки

Принятие записывается в Trajectory событием `input.applied`: исходный `run_id`, граница операции и полные принятые сообщения. Весь запуск остаётся связан одной задачей. Не запущенные tools сохраняют свои call IDs и явную причину пропуска. [Полный ZIP-экспорт](trace-export.md) включает эти записи вместе с остальной трассой.

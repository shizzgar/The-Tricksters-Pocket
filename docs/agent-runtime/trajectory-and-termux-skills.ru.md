# Trajectory и полные пакеты навыков в Termux

В меню «+ → Trajectory» доступны два режима: **Waterfall** с общей шкалой времени
и **Поток** с последовательностью операций и ссылками на исходный запрос модели.
Запросы и инструменты связываются по ID, поэтому параллельные запросы не склеиваются.
Выбор запуска сужает временную шкалу. Масштаб 1–16× и горизонтальная прокрутка позволяют
рассмотреть короткие операции внутри длинного запуска. Полосы показывают записанное
время выполнения; светлый участок запроса — ожидание первого контента, когда оно измерено.

Нажатие на операцию открывает обзор, вход, выход и исходные события. На широком экране
инспектор расположен рядом с диаграммой. Для подагента можно открыть его собственную
трассу и вернуться к родительской. Поиск по названиям/командам/ошибкам работает сразу;
«Искать в содержимом» дополнительно читает полные сохранённые payload. Результаты
относятся к загруженному окну: начальные 600 событий расширяются до 20 000 кнопкой
загрузки истории, после чего можно перейти к предыдущему окну или вернуться к последним
событиям. Старые записи не переписываются; компактные сводки новых событий
проверяются той же цепочкой хешей, что и журнал.

Отсутствие завершающего события не означает успех. Такие операции помечаются «Нет
завершения»; новый запуск не оживляет старые оборванные запросы. TPS использует только
измеренное время получения потокового контента. Неизвестные метрики обозначаются «—».
Время всей полосы включает ожидание модели, а время всей задачи может включать паузы.
Журнал хранится локально и содержит пользовательские данные. Детерминированный replay
и восстановление событий, которые старые версии не записывали, не добавлены.

## Навыки

1. Установите Termux, разрешите RUN_COMMAND и включите `allow-external-apps=true`, как
   описано на существующем экране интеграции. Установите Python: `pkg install python`.
2. В «Настройки → Termux → Навыки в Termux» включите передачу пакетов. Автоматическая
   подготовка при `use_skill` включена по умолчанию. Можно отключить её и оставить
   явный вызов `termux_skill_sync`.
3. Включите нужные навыки и инструменты Termux для ассистента. Только эти навыки
   доступны через его `use_skill`/`termux_skill_sync`. Навыки с автоматической загрузкой
   текста вызывают `termux_skill_sync` перед первым использованием файлов в Termux.
4. Успешная подготовка возвращает **skill_root** — точный каталог версии. Агент передаёт
   его как `working_dir` в инструменты Termux и выполняет, например,
   `python3 scripts/report.py`. Соседние `references/`, `assets/`, шаблоны и бинарные
   данные доступны относительно этого каталога. Выходные файлы следует писать в рабочий
   каталог задачи, отдельно от исходников навыка.

ZIP и импорт каталога GitHub сохраняют файлы побайтно. Импорт одного Markdown URL
по-прежнему импортирует только этот документ: для ресурсов нужен полный пакет.
Пакет ограничен 200 файлами и 20 МиБ. Передача идёт порциями до 48 КиБ через RUN_COMMAND,
без общего хранилища Android и без обхода разделения UID приложений. В Termux проверяется
SHA-256 архива, затем готовый каталог публикуется атомарно. Незавершённый перенос можно
повторить; он не исполняет скрипты навыка. Символические ссылки и выход за пределы пакета
отклоняются. Скрипты получают executable-бит, но для shebang другого ОС используйте
интерпретатор Termux явно. Системные и Python/Node-зависимости автоматически не ставятся.

Настройки позволяют выбрать каталог внутри Termux home, синхронизировать все установленные
навыки, проверить число копий/занятый объём и удалить копии после подтверждения.
Каталог дополнительно разделяется по package ID приложения: debug и release не пересекаются.
Версии сохраняются, чтобы обновление не подменило файлы под работающим заданием.
Лимит хранилища — 256 МиБ. При его достижении остановите использующие навыки задания,
очистите копии и синхронизируйте нужные пакеты. Смена каталога не удаляет прежний.
Изменения файлов в Termux не переносятся обратно в RikkaHub; изменённая копия обнаруживается
при проверке и не перезаписывается поверх работающего кода. Отключение интеграции не удаляет
уже переданные файлы и не отзывает у Termux доступ к его собственному хранилищу.

## Проверка

Python-тесты выполняют перенос пакета, проверяют бинарный ресурс, реально запускают
тестовый скрипт из перенесённого каталога, проверяют обрывы, повторные порции, хеши,
ограничения, небезопасные пути и сохранение предыдущих версий. JVM-тесты проверяют
детерминированный экспорт и корреляцию трасс, старый формат журнала, отмену и потерю
процесса. Instrumentation-тесты на Android проверяют переходы Waterfall → Поток → Вход,
сохраняют снимки английского интерфейса и русского интерфейса в тёмной теме.

## Мастерская навыка и инспектор операций

В «Расширения → Навыки → нужный навык» пакет открывается как файловая мастерская.
Доступны папки и навигация по пути, поиск по всему пакету, сортировка, множественный
выбор, создание, переименование, перемещение, дублирование и удаление. «Добавить файлы»
импортирует ресурсы через системный выбор документов; совпадение имён не перезаписывает
старые файлы. Для замены одного файла есть отдельное действие в редакторе. Экспортируется
один сохранённый файл либо весь пакет в ZIP. Пустые папки остаются в приложении;
передача в Termux и ZIP сохраняют файлы и необходимые для них каталоги.

Редактор поддерживает UTF-8, подсветку кода, номера строк, перенос, поиск и замену,
переход к строке и undo/redo. Markdown имеет предпросмотр; изображения открываются без
исполнения содержимого. Бинарные файлы показываются побайтно и могут редактироваться
в HEX. Пределы интерактивного редактирования: 256 КиБ / 4000 строк текста либо 64 КиБ бинарных данных.
Более крупные файлы можно заменить и экспортировать; общий лимит пакета остаётся 20 МиБ
и 200 файлов. В свойствах показаны размер и SHA-256 сохранённой версии.

Черновик записывается после короткой паузы ввода и восстанавливается при следующем
открытии мастерской. Выход или переход с несохранённым текстом предлагает сохранить
либо отменить правки. Сохранение проверяет версию всего пакета и хеш открытого файла:
конкурирующая правка агента не затирается. При конфликте черновик остаётся доступным
для копирования; можно перезагрузить сохранённый файл и повторно внести изменения.

Файловые изменения проходят через временный каталог. Предыдущее состояние всего пакета
доступно в меню «Восстановить предыдущую версию» до следующей файловой операции.
Временные версии и черновики лежат вне пакета и не попадают в ZIP или Termux.
Прерванная публикация восстанавливается при запуске до установки встроенных навыков.
Навык, изменённый в мастерской, помечается пользовательским: обновление встроенного
пакета не заменяет его правки. Для возврата к поставляемому пакету удалите навык и
установите его повторно из каталога. Корневой SKILL.md нельзя удалить или переместить,
а его имя навыка и обязательное описание проверяются перед сохранением.

Кнопка синхронизации в мастерской передаёт сохранённый пакет в новую версию Termux
и позволяет скопировать skill_root. Ранее запущенные задания используют прежние версии.
Файлы, изменённые непосредственно в Termux, обратно не импортируются автоматически.

В инспекторе Trajectory контекст операции, времена и действия доступны на всех вкладках.
На широком экране они занимают отдельную колонку. Есть переходы к соседним и связанным
операциям, хронология событий, копирование ID/содержимого и экспорт событий выбранной
операции в JSON через системный диалог. Экспорт содержит записанные входы и результаты.

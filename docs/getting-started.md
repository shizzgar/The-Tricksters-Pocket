## 1. Установка

Нужны Android 8.0+ (API 26) и ARM64 либо x86_64. Готовый артефакт CI рассчитан на **ARM64**. Для x86_64 можно собрать APK из исходников.

1. Откройте [Agent runtime debug APK](https://github.com/shizzgar/rikkahub-agent/actions/workflows/compaction-debug.yml).
2. Выберите успешный прогон нужной ревизии `master`. Убедитесь, что это репозиторий **shizzgar/rikkahub-agent**.
3. В **Artifacts** скачайте **rikkahub-compaction-arm64-debug**. Для скачивания артефактов GitHub может потребоваться вход в аккаунт.
4. Распакуйте ZIP и установите `rikkahub-compaction-arm64-debug.apk`. Рядом находятся `COMMIT.txt` и `SHA256SUMS`.

[Проверенная сборка `81fea68` от 23.09.2026 →](https://github.com/shizzgar/rikkahub-agent/actions/runs/35875085640/artifacts/10759050850)

Артефакты CI хранятся **14 дней**; у указанной сборки срок хранения до 07.10.2026. Если артефакт уже удалён, выберите новый успешный прогон или [соберите приложение](building.md). Доступный владельцу репозитория **Run workflow** позволяет повторить сборку. Это канал debug-сборок, а не стабильный release-канал.

### Обновление и данные

Debug-сборка использует ID `excp.rikkahub.debug`, release — `excp.rikkahub`, исходный RikkaHub — `me.rerere.rikkahub`. Это отдельные установки со своими данными и разрешениями.

Перед переносом данных используйте **Настройки → Резервная копия**. Обновление поверх установленного APK требует совпадения package ID и сертификата подписи. Чистая CI-сборка может получить другой debug-сертификат. Ошибка подписи не означает, что нужно удалять основное приложение; сначала сохраните резервную копию и проверьте, какую именно установку обновляете.

## 2. Модель и поиск

В настройках провайдеров добавьте используемый endpoint/API-ключ и выберите модель. Для команд и skills нужна модель с поддержкой tool calling. Приложение поддерживает провайдеры и совместимые endpoints, унаследованные от RikkaHub/ExTV.

**Local search** здесь означает web-поиск через настроенного в приложении провайдера, а не поиск файлов в Termux. Настройте его в разделе поиска. Если у модели включён собственный встроенный поиск, в меню поиска чата переключите режим на **Local**, чтобы использовать провайдера приложения.

## 3. Ассистент и tools

Выберите ассистента, откройте его **Локальные инструменты** и включите нужные группы. В **Отдельных инструментах** есть поиск и выключение конкретных tools внутри доступных групп.

- **TTS**, распознавание с микрофона и **Whisper** включаются отдельно. Whisper требует Termux.
- **Создание и редактирование навыков** разрешает агенту менять подключённые пакеты и создавать новые. По умолчанию эта группа выключена.
- Если skills не подключены или отсутствуют на диске, skill-tools и автоматические skill-инструкции не добавляются в запросы модели. Для создания первого пакета агентом подключите один существующий skill.

Набор tools обновляется перед следующим запросом модели. Уже выполняющийся вызов переключателем не отменяется. Настройки подтверждения действий продолжают действовать.

## 4. Termux и файлы skills

1. Установите и один раз откройте [Termux](https://github.com/termux/termux-app).
2. Следуйте **Настройки → Termux** в RikkaHub Agent: предоставьте разрешение RUN_COMMAND и включите `allow-external-apps=true` в конфигурации Termux. Разрешение нужно именно установленному экземпляру приложения.
3. В Termux установите Python:

   ```sh
   pkg install python
   ```

4. Включите **Termux** в локальных инструментах ассистента.
5. Откройте **Настройки → Termux → Навыки в Termux**, включите передачу пакетов. Автоматическая подготовка при `use_skill` включена по умолчанию; её можно заменить явным `termux_skill_sync`.
6. Подключите навык ассистенту. Для импорта ресурсов используйте ZIP или каталог GitHub: импорт отдельного Markdown URL содержит только документ.

После успешной синхронизации агент получает **`skill_root`**, каталог конкретной версии пакета. Используйте возвращённый путь, не угадывайте его. Результаты и рабочие файлы задачи храните отдельно от исходников skill.

Синхронизация не исполняет скрипты и не устанавливает их зависимости. После редактирования навыка синхронизируйте новую версию; работающие jobs продолжат использовать старую. Правки из Termux автоматически не возвращаются в приложение.

## 5. ReBro

Выберите **ReBro** в списке ассистентов. Kit уже встроен: 10 навыков и 253 файла, отдельно импортировать архив не нужно. Termux и Local search включены в профиле; шаги настройки разрешений, модели и провайдера поиска всё равно необходимы.

Промпт содержит датированный профиль SM-S928B / Android 16 и известную конфигурацию Frida из исходного kit. На другом телефоне адаптируйте сведения об окружении. Установка приложения не меняет Frida, не запускает скрипты и не выдаёт root-доступ.

[Полное описание ReBro](agent-runtime/rebro-assistant.ru.md).

## 6. Где смотреть происходящее

| Нужно узнать | Где открыть |
|---|---|
| Что делает агент и какие запросы/команды связаны | **«+ → Трассировка диалога»** |
| Вход, выход, ошибки и длительность операции | Нажать на операцию в Waterfall/Flow |
| TPS, usage, ожидание и полное время ответа | Строка статистики под сообщением |
| Состояние фоновых команд | **«+ → Background jobs»** и карточки Termux tools |
| Файлы, редактор и синхронизация skill | **Расширения → Навыки → нужный навык** |
| Таймауты генерации и compaction | **Настройки → Модели** |

Если возникла ошибка, подготовьте [баг-репорт по инструкции](../CONTRIBUTING.md#report-a-bug). Укажите коммит сборки, устройство, шаги воспроизведения и релевантный фрагмент лога. Экспорт Trajectory может содержать приватные данные — проверьте его перед публикацией.

# Оркестрация по результатам этапов

## Выбрать цель и маршрут

Точка входа — rebro-workflow для сложной задачи; для точечной подписи/диагностики
можно прямо вызвать профильный навык. Список включённых навыков известен из RikkaHub;
оркестратор не исполняет другой skill магически: вызывает use_skill, получает
skill_root, запускает скрипт и проверяет результат. Отключённый навык обозначить
как недоступный, не угадывать его приватный путь.
Для любого нового APK case требуется включённый `rebro-environment`; orchestrator
и sign не содержат его doctor. Даже короткий sign-only маршрут вызывает этот навык.

| Запрос | Минимальный маршрут |
|---|---|
| «Понять функцию приложения» | environment → acquire → analyze; Frida при необходимости |
| «Патч и готовый подписанный APK» | environment → acquire → analyze → patch → build → sign |
| «Подпиши этот готовый APK» | environment → intake(candidate) → sign |
| «Установи и проверь полученный патч» | продолжить от проверенного signed receipt → install → verify |
| «Frida перестала цепляться» | environment + rebro-frida diagnosis; без APK rebuild |

Работать в существующем разрешённом scope. Выяснять только действительно
неопределённые package/user, цель патча и signing identity, которые меняют действие.
Не повторять вопросы, уже разрешённые в текущей задаче.

## Движение состояния

Каждый этап: проверить parent → begin → действие → inspect outputs → finish.
Started/running — не pass. Failed хранит ошибку; blocked — конкретный недостающий
вход/условие; unknown — операция могла произойти и требует сверки с реальностью.
Ни один из этих статусов не подходит как parent следующего этапа.

При новом варианте патча создать новую ветвь attempts с нужным parent receipt.
Старый успешно подписанный set сохраняет своё происхождение; не объявлять его
результатом новой сборки. Не переназначать «current» по последнему имени каталога.
Изменение байтов уже зафиксированного артефакта обнаружится `caseflow check`.

Пример начала full case:

```sh
python3 scripts/caseflow.py init --case "$REBRO_CASE" \
  --package com.example.lab --android-user 0 --mode full
python3 scripts/caseflow.py begin --case "$REBRO_CASE" --stage environment
```

Затем вызвать rebro-environment, выполнить doctor в отдельный файл и завершить
environment с evidence=doctor.json и output=этот файл. Сохранять **выданные** пути
attempt/receipt, не конструировать UUID. Свежесть RAM/disk проверять также перед
тяжёлой задачей, даже если environment receipt старый, но целостный.

Для подписи готовых файлов Android user не нужен:

```sh
python3 scripts/caseflow.py init --case "$REBRO_CASE" \
  --package "$PACKAGE" --mode sign-only
```

Если позднее в задачу входит установка, перед install привязать фактически выбранный
профиль: `python3 scripts/caseflow.py bind-user --case "$REBRO_CASE" --android-user "$ANDROID_USER"`.
Уже завершённые artifact-only receipts с user=null остаются валидными.

## Единый статус для ответа пользователю

Сообщить последний доказанный этап, путь к пригодному артефакту, проведённые
проверки и конкретную незакрытую границу. Примеры:

- «Подписан полный набор, certificate соответствует профилю; установка не входила в задачу».
- «Журнал дошёл до commit_requested, ответ потерян; установленный set ещё не совпал — исход неизвестен».
- «Установка и целевой тест прошли; соседний сценарий не проверен, функциональный gate не закрыт».

Не говорить «патч работает» по одному успешному apksigner. Не говорить «установка
не состоялась» по потере транспорта. Конкретные пользовательские факты и API-схемы
приоритетнее шаблонного сценария; при несовместимой версии parser остановить этап
с evidence и адаптировать его отдельным контролируемым изменением.
